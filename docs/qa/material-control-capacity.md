# Full-queue material control

Material handoff freezes every older valid queued command and appends its exclusive marker last. It cannot require an ordinary tick to drain a retired owner, nor overtake an older tail when the queue exceeds the normal upload budget. Invalid cell indices retain existing ignore-on-commit behavior; inputs added by completion callbacks belong to the next step.

`PrepareMaterialHandoff(batch, orderedCommandCount)` reserves existing command/delta scratch storage before dispatch. Both generic and native backends allocate a complete candidate pair before publishing either handle, release candidates on allocation failure, and release replaced handles exactly once. Cell, transport, material and visual buffers are unchanged. Every dispatch binds the current pair. Ordinary Tick, acknowledged inputs and ash collection continue to use the original per-step admission budget, including simulators constructed around an already-grown generic buffer grid.

For N earlier valid commands, command capacity is N+1 at 16 bytes per element. Delta capacity conservatively uses cellCount+commandCount at 20 bytes per element; the marker itself emits no delta. Element counts and byte products are checked before allocation. An unallocatable backlog fails before dispatch rather than dropping inputs. Preparation failure is NotApplied and retains the queue/authority; an attempted preparation consumes its token, so retry uses the next token. Failure after entering the existing apply boundary remains conservatively Indeterminate. Unexpected rejected GPU handoff still simulates unchanged material and remains a separate caller fail-stop condition.

No HLSL, buffer binding names, 16-byte ordinary/ash command encoding, 40-byte material receipt row, 20-byte target/slot delta, eight-UAV kernel contract or snapshot schema changed.
