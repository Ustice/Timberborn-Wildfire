# Warden construction parent and native doorstep

The [actual placement attempt on fd13bef](warden-pivot-placement-live.md) passed cursor preview, then failed in `BuildingDoorstepSpawner.SpawnDoorstep` at IL0021. The installed method gets `BuildingModel.UnfinishedModel` and immediately dereferences its transform. The station declared an empty `UnfinishedModelName`, so native `BuildingModel.Awake` deliberately left that reference null.

Native doorstep admission checks a positioned entrance at BaseZ and the absence of `DoorstepSpawnDisablerSpec`. It does not exempt buildings with `PlaceFinished=true`; native entity initialization occurs before the immediately finished transition. All installed building blueprints with entrances provide an unfinished model parent. The two explicit doorstep-disabling monuments also retain their unfinished models.

The station now names a distinct `#Unfinished` child containing the installed `ConstructionBase3x3` nested blueprint. That foundation matches its 3×3 footprint and provides the native doorstep parent. The existing finished mesh remains separate because native model visibility toggles finished and unfinished objects independently. The fix does not disable doorstep creation or alias both roles to the finished mesh. Construction stages, cost and science unlock remain release work.

`NativeWardenDoorstepContractTests` runs the actual installed doorstep admission predicate and native Newtonsoft spec deserializer, then verifies the referenced child and installed foundation footprint. Its fixture supplies component-cache state and already-positioned entrance presence; it does not run placement, Unity transforms, native prefab instantiation or the complete `BuildingModel.Awake` lifecycle. The initial fixture needed that entrance presence before it reached the relevant native branch. Once corrected, the station contract failed while two native faction Builders Hut controls passed. The blueprint fix passes all three; the full native suite passes **1,310 tests**, with zero failures or skips. The separate generated fuel blueprint check passes **375 blueprints**; it is not a general validator for custom station lifecycle requirements.

The adjacent source audit found that `BuildingModel` already supplies the interface that adds `BlockObjectModelController`; existing `#Finished` satisfies its required finished-model consumers. Optional uncovered and underground names can be empty. `ConstructionSiteProgressVisualizer` is installed only by its own spec and expects stage thresholds to match its children, so copying another building's stage settings onto this foundation-only prototype would be incorrect. This is a bounded audit of reviewed initialization consumers, not a guarantee about every later native lifecycle.
