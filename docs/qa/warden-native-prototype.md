# Native Ironteeth warden prototype

Status: integrated with the QA command gate and original station/gear meshes; 610 native-project tests pass on 2026-09-07 against the installed macOS game assemblies. This is source/API and isolated protocol evidence. Native placement, worker assignment, actual trips, visuals, accounting UI, and save/reload remain unverified until the sole live QA controller can access Steam. The station uses its canonical Ironteeth model; gear assets are packaged but are not attached to characters.

## Ownership and native contracts

`FireResponse` owns one dedicated station worker. `WardenStation` is a native `WorkplaceBehavior`; its marker spec installs a dedicated capacity-20 `Inventory`. `AdultSpec` installs a component executor and a separate capacity-one private equipment inventory. Native `BehaviorManager` finds that registered executor component on restore. CarryRoot remains available to replenish the station through native carrying/reservations; the response payload uses the private inventory so it does not become an unrelated carrier delivery job.

Both inventories declare input-only `StorableGood.CreateAsGivable(Water)`. Native input goods are counted through `IGoodProcessor`; station public stock must not also declare output because the native stock counter would count it a second time. The character's plain processor proxy explicitly follows citizen district assignment: attaching `IGoodProcessor` to a character would activate a native decorator requiring `DistrictBuilding`. Native inventory registration attaches consumption observers. These conclusions come from installed IL, not observed live resource totals.

The executor reserves one native station Water, transfers it to equipment using `TakeExisting`/`GiveExisting`, walks to a safe sampled approach, prepares a single `AddWater: 3`, then returns. The simulator decides the dose's effect. One unit is consumed with native `TakeConsumed` only in the exact step commit callback after readback/swap and before simulator listeners. Capacity rejection neither enqueues nor consumes a dose. AwaitingApplication and loaded native equipment are the pending state; no separate water ledger or global pending-input queue is persisted.

Native inventory calls mutate before invoking potentially throwing events. Paired refill/return operations and simulator consumption therefore share an in-flight save guard. An ambiguous operation freezes future fire dispatch and rejects save; it never guesses a refund or replay. Only loading/unloading a saved world resets that guard. Installed normal save capture synchronously serializes entities then singleton state before creating its destination file; the runtime guard runs before the old-payload fallback. Callback reentrancy is also guarded. Native fault injection has not been executed.

Native candidate routes are screened, then the actual newly installed Walker path (including its start prefix) is checked via `StartedNewPath`. A changed field refreshes the route before another executor walk tick. Initial hazards permit only bounded escape toward safer cells; ingress cannot cross them. Stopped walks must physically reach their destination to count as arrival. This is sampled prototype safety, not a global navigation-cost change or civilian avoidance guarantee.

## Copied-save live acceptance

Only the assigned live controller performs these steps after checking the QA lock and process state. Follow the deploy runbook and use an expendable Ironteeth save with employed adults, connected paths, clean Water storage, and suitable burnable trees. Keep a known-good pre-test save.

1. Deploy the integrated code plus canonical station timbermesh. Launch with the explicit [QA mutation opt-in](../release/qa-command-access.md) and verify `command_access=development` before using forced stimuli. Load the copied save, enable development tools, and place **Warden Station (prototype)** from Water. It is currently free and immediately finished. Verify native placement, footprint, front +Z entrance, one beaver worker slot, district registration, pause, and native capacity. No missing component/template/atlas exceptions are acceptable.
2. Confirm active simulation with `bun scripts/invoke-timberborn-command.ts qa-readiness --wait=6 --require-advanced-tick`. Use `bun scripts/invoke-timberborn-command.ts qa-delta-stimulus tree --wait=6 --require-advanced-tick` to locate a reproducible fire target from its output. Place/connect the station within 20 cells of that target with a clear two-cell approach. The stimulus chooses an imported target; do not assume it chose the nearest tree. Retain output coordinates and actual fire behavior.
3. Observe replenishment through native carrying, reservation release, and physical station arrival. Capture station inventory, district total, and consumed Water before/after each leg. Log lines prefixed `wildfire_warden` include entity ID, phase, target index, and status. Require a physical trip, preparation, `Water applied`, and safe return. With other water consumption controlled, transfers conserve total Water and one committed application consumes exactly one. A changed fire cell alone is insufficient receipt evidence (saturation can produce no delta).
4. Save/reload independently during Fetching, Approaching with loaded equipment, Applying, AwaitingApplication, and Returning. Read native inventory components `Wildfire.WardenStation` and `Wildfire.WardenEquipment` and executor component `Wildfire.WardenExecutor` in each saved entity. Pending save must contain loaded equipment plus pending phase; committed save must contain the consumed inventory and fire snapshot from the same boundary. Verify exactly one eventual application, no duplicate refill, correct restored worker, and no root/carry takeover of the equipment. If a phase cannot be captured at native save cadence, record that limitation and add a targeted controller fixture rather than claiming coverage.
5. Interrupt independently by extinguishing the target while outbound, pausing/destroying the station, dismissing the worker, disabling Wildfire, obstructing the route, introducing fire/smoke on the remaining route, and making the current cell hazardous. Confirm cancellation, released source reservations, water retained or returned, no false arrival, safe escape where available, and native needs/work resume. If no safe route exists, the prototype releases control and retains water; it makes no civilian safety claim. Re-enable/reassign and verify a later valid response.
6. Repeat with two stations and near-full external-input capacity. Each admitted dose consumes one Water; rejection retains loaded pending state. Pure tests already cover input rejection, commit order/outcomes, callback/transfer failures, and save guards. Actual GPU/native event failure injection and multi-worker live accounting remain separate evidence gates.

## Station panel and recovery warning

The station uses native `IEntityPanelFragment` registered through `EntityPanelModule`, alongside native worker controls. It displays station reserve, assigned worker count, the assigned worker's equipment water, the configured 20-tile response radius, and localized phase/failure text. Coverage text describes a search radius with required safe paths; it does not promise every fire is reachable. The display reads existing native state without requesting GPU observations. Typed reasons do not parse diagnostic log strings. Historical reasons are presentation-only and are not persisted; restored sortie phases remain authoritative. A restored return never implies that water was applied.

`WardenRecoveryNotification` polls the already-established unsafe state from its own native singleton update, including while fire dispatch is frozen. It latches before invoking `QuickNotificationService.SendWarningNotification`; notification exceptions are caught at this UI boundary and cannot clear the save guard or replace an inventory exception. The station panel retains the recovery instruction even if the quick warning fails or expires. Only a native world load rearms the notice. Pure tests cover priority of recovery text, pending versus applied water, return status while paused, and a throwing/reentrant notification with the water save guard still active.

Live UI gate: select/deselect the station and unrelated entities, verify layout/text wrapping in the current theme, check native worker controls remain usable, then observe reserve and equipment counts through replenishment/application/return. Pause/unpause and dismiss/reassign a worker; phase and failure text must follow native state without stale success claims. Reload an in-progress return and confirm it does not claim a dose was applied. A controlled failure fixture must separately prove one recovery warning per loaded world, persistent panel instruction, rejected saving, and reset only after actual reload. No native warning subscriber fault or rendered panel has been exercised by the source-only tests.

Native UI contract evidence (installed macOS assemblies): `EntityPanel.ShowFragments` invokes every registered fragment for the selected entity. `BaseComponent.GetComponent<T>` delegates to `ComponentCache.GetCachedComponent<T>`; the absent-index branch returns default(T), while duplicate matches throw. Native `WorkplaceFragment.ShowFragment` uses the same GetComponent-then-presence-check pattern. The warden fragment therefore hides safely for ordinary unrelated entities; duplicate registrations remain a real configuration error. Validation for the UI increment: 617 native-project tests passed, with 31 unique Warden localization rows checked.
