# Existing beaver exposure dispatch: capability and fairness correction

The worker-speed actuator returns `Unsupported("fire_heat_actuation_unavailable")` for `FireHeatExposureAttempt`. It does not move or injure a beaver. Smoke actions keep their existing behavior; the existing `NoOp` sample progression remains an applied dispatcher decision.

Unsupported apply results return before successful state, last-decision tick/cooldown, accumulated exposure, or Applied counters are written. This preserves a previous smoke action and its native recovery handle through unsupported fire observations and component state save/load. Unsupported recovery likewise retains the pending cleanup state. Definite Failed/unknown actuator results throw and increment Failed; thrown actuator callbacks propagate unchanged. Neither is downgraded to unsupported or automatically retried within dispatch. A callback that mutates then throws remains a separate native transaction problem; this correction does not establish cross-dispatch replay safety for future injury effects.

The limit is successful applications per dispatch, including existing NoOp progression. Unsupported and cooling actors encountered before the limit do not consume it. Once full, remaining eligible actors are deferred without probing their actuator. Candidates are ordered by never-applied, then oldest persisted `LastDecisionTick`, then ID. With advancing simulation ticks, later IDs therefore progress even when earlier actors remain continuously eligible. The existing positive cooldown validation remains. Repeated/null synthetic ticks do not establish elapsed exposure or guarantee a new scheduling interval. No persistence version, injury dose, exposure time model or native health state changed.

`DecisionsEvaluated` and observed smoke/fire counters include all exposed candidates examined, even if cooling or deferred. `UnsupportedDecisions` counts actual unsupported actuator results, not all deferred actors. QA exposes `beaver_field_behavior_unsupported_decisions`; Applied counters remain distinct. Legacy `FireHeatActiveFlameContacts` / `fire_heat_active_flame_contacts` is a **nearby visual flame proxy**, based on the existing neighborhood maximum threshold, not measured bodily contact. Logs and QA explicitly add `fire_heat_contact_basis=nearby_visual_proxy` (with the existing QA prefix). No movement or injury is inferred from these counts, and removing the old counter exception does not complete civilian avoidance.

Focused tests use the real worker-speed actuator over a recording native-speed adapter for mixed unsupported fire plus supported smoke, preserving/restoring prior smoke cleanup, and 130 continuously exposed actors across cooldown and save. Definite Failed and a deliberately mutating throwing actuator show that the batch halts and no false Applied state is committed. The QA result test verifies unsupported and visual-proxy telemetry. Full native test project: **707 passed, zero failures/skips** using `dotnet test tests/Wildfire.Timberborn.Tests/Wildfire.Timberborn.Tests.csproj --no-restore --verbosity minimal`. These are managed/source checks, not game proof.

Independent smoke/fire progression, physical cell/contact exposure, elapsed injury intervals, native injury callback uncertainty, broader civilian escape and loaded-cargo recovery remain separate release work. The existing FireHeat variant still takes priority for a mixed observation; this correction does not invent a new physical rule to fill that gap.
